## 要对齐的差异（逐条）

### 1. 学员端「运营现状 / 上线后的表现」补齐为原型的 4 指标布局

现状：只显示「累计浏览量」大数 + 「今日浏览」。
原型（见 student.txt）：
```
运营现状
上线后的表现
1,284            ← 累计浏览量（大号数字）
186   94   +18%  ← 横向三栏小指标
今日浏览 独立访客 近7天
```

要做成：顶部大号「累计浏览量」，下方**横向三栏**「今日浏览 / 独立访客 / 近 7 天」。
- 「今日浏览」用 `stats.today_views`（后端已有）
- 「独立访客」和「近 7 天趋势」后端目前**没有这个数据**。**不要编造数字**——显示 `—`，下方小字标注维持原样。近 7 天那一栏若为正增长用 `--success` 绿色（原型 `+18%` 是绿的），无数据时不上色。
- 这三栏的排版、字号、间距参照原型：数字用 20px 左右加粗，标签用 `--ink-soft` 小字。

> 为什么不编数字：产品原则是「AI 解释而非技术堆叠、不编造数据」（需求文档 §14.6）。位置留出来，数据 P1 接入 umami 后再填。

### 2. 学员端「开发完成度」每个诊断项左侧加维度图标

现状：每项是纯文字 + 进度条。
原型：每个维度左侧有一个约 32px 的**蓝色圆角方块图标**（`--surface-soft` 底 + `--blue` 图标）。
要做：给 6 个诊断项各加一个小图标（用简单的 inline SVG 或 emoji 皆可，风格要克制，跟原型的细描边低阴影一致）。图标语义可按维度选（首页/文件/预览/数据/流程/内容）。

**不要把 6 项改回 2 项**——6 个可解释诊断项是刻意的设计（需求文档 §9.1.3 硬要求「百分比必须能被诊断项解释」）。保留 6 项，只是让每项的视觉更像原型的维度卡。

### 3. 老师端审核详情右上三列——保留分数，排版贴近原型

现状：「前端 20/20分 ✓已验证 / 服务端 20/20分 ✓已验证 / 线上版本 v0.3.0」。
原型：「前端 已完成 / 服务端 已连接 / 线上版本 v1.1.0」（纯状态词，蓝色）。

**保留分数和证据分级**（这是信息升级，比原型的纯状态词更有价值），但：
- 主行显示一个**状态词**（前端→根据分数给「已完成/完善中」，服务端→「已连接/未连接/不适用」），跟原型一样用 `--blue`
- 分数和 `✓已验证` 作为**次要小字**放在状态词下方，不要喧宾夺主
- 「服务端」维度如果诊断里是 `not_applicable`，显示「不适用」而不是「0/20分」

### 4. 侧边栏导航图标与原型对齐

原型侧边栏图标是**线性描边风格**（home / folder / clipboard 或 history / book）。
如果当前实现的图标风格不一致（比如实心方块），换成线性描边风格，`--ink-soft` 描边、约 20px。
学员端顺序：概览 / 我的项目 / 提交记录 / 作品集合。
老师端顺序：总览 / 项目 / 审核 / 集合页。
