# VibeHub PRD v1 · 可开工版

> **本文与《产品需求文档.md》的关系**：那份文档（乐乐老师）定义了**产品是什么**，写得很完整，本文不重新定义它。本文补的是它 §15 明确声明「暂不定义」的部分——范围边界、角色权限的可执行版本、验收标准、非目标、以及开工前必须钉死的东西。
>
> 两份文档冲突时，以那份为准（产品概念），以本文为准（工程范围）。

---

## 1. 产品定位

**一句话**：给零基础学员一条「作品从做出来到公开上线」的完整通道，同时给老师一个「看得见、审得了、能汇总」的管理台。

**它不是什么**（这一条比是什么更重要）：
- ❌ 不是通用的代码托管或 CI/CD 平台
- ❌ 不是给学员提供服务器的 PaaS
- ❌ 不是 AI 编程工具（学员用自己习惯的 Claude Code / Codex / WorkBuddy）
- ❌ 不是课程管理系统（考勤、成绩、排课都不做）
- ❌ 不做商业化、支付、复杂数据分析（需求文档 §15 已排除）

**它就是三件事**：把作品变成网址 · 让老师能审 · 把作品聚起来展示。

## 2. 目标用户与首场落地

| 角色 | 典型画像 | 最在意的事 |
|---|---|---|
| 学员/参与者 | 零基础，会用 AI 工具，不懂服务器、域名、部署 | 我的作品有没有上线？网址是什么？我能发给别人吗？ |
| 老师/主创 | 要同时看 20–30 个学员的进度 | 谁卡住了？这个版本能不能发？发出去会不会出事？ |
| 访客/家长 | 通过链接或二维码进来 | 这些孩子做出了什么？ |

**首场落地场次**：〔待定，见决策 7〕— 这是 P0 范围的唯一裁剪依据，没有它 P0 会无限膨胀。

## 3. 范围裁剪标准

抄自 `ai-game-camp-platform` 的 MVP 收敛方法：**只做「没有它营就开不起来」的东西**，其余一律 P1/P2。

判据：如果这个功能缺席，开营第一天会不会爆炸？
- 学员部署完打不开 → **会爆炸** → P0
- 老师看不到谁没开始 → 会很难受但能用飞书表格顶一下 → 但需求文档 §7.7 明确要求且实现成本低 → P0
- AI 诊断的文字建议不够好 → 不会爆炸，先给模板文案 → P1

## 4. P0 用户故事与验收标准

### US-1 老师开课并分发邀请码
> 作为老师，我要建一个课程并批量生成邀请码，这样学员才能接入。

**验收**：
- 建课程时填名称、类型（课程/房间/征集/黑客松）、主题、简介，即可保存
- 一次生成 N 个邀请码，明码**只在生成时展示一次**，可导出 CSV 供线下分发
- 列表页只显示后 4 位与状态（未使用/已绑定/已撤销/已过期），不回显完整码
- 撤销任一邀请码后，该码签发的所有 AI 工具凭证**立即失效**（下次调用返回 401）

### US-2 学员在自己的 AI 工具里接入
> 作为学员，我在 Claude Code 里输入邀请码，就能把我的项目跟平台连起来。

**验收**：
- `vibehub bind SUMMER-7K3P` 成功后终端显示「已连接到《AI 产品共创课》，你的作品：城市声音地图」
- 凭证写入 `~/.vibehub/credentials.json`，权限 0600
- 同一邀请码最多绑定 `max_devices`（默认 3）台设备，超出给出人话提示
- 错误场景全部有中文提示：码不存在 / 已撤销 / 已过期 / 设备数超限

### US-3 学员提交并拿到预览
> 作为学员，我写完就 deploy，马上能看到自己的网页长什么样。

**验收**：
- `vibehub deploy` 自动检测：有 build 脚本就先构建、只上传产物；否则打包当前目录
- 自动排除 `node_modules` `.git` `.env` 及 `.vibehubignore` 指定项
- 内容与上次完全相同时不重复上传，提示「内容和上一版完全一样」
- 上传成功后**立即**返回预览地址（不等诊断），终端可点击
- 包里没有 `index.html` 时，报错信息是人话：「没找到 index.html，你的网页需要有一个首页文件」
- 预览地址不可猜（16 位随机），且不会被搜索引擎收录

### US-4 老师审核并发布
> 作为老师，我在审核队列里点开一个版本，看到它长什么样，决定发不发。

**验收**：
- 队列按提交时间倒序，显示学员姓名、作品名、版本号、时间、状态点
- 点开能直接在页面内预览该版本的真实内容（iframe）
- 显示「本次更新」说明、诊断摘要（前端状态/服务端状态/完成度）、当前线上版本号
- 「审核并发布」后，作品的正式网址在 **3 秒内**指向新版本，且切换过程中访客不会看到 404
- 「退回修改」必须填写原因，学员在 `vibehub status` 和网页看板都能看到这个原因
- 重复点击「审核并发布」不会造成二次发布，提示「这个版本已经处理过了」

### US-5 学员看到自己的看板
> 作为学员，我打开网页就知道现在什么状态、下一步做什么。

**验收**（对应原型 `#student`）：
- 顶部显示作品名 + 当前状态徽章 + 版本号 + 更新时间
- 「现在的项目长这样」展示最新版本的真实截图或 iframe
- 「你的网页」显示正式网址 + 二维码 + 复制/打开按钮；**未发布时此区块显示「还没有正式上线」而不是空白**
- 「两个版本，要分清」同时显示当前线上版本与新提交版本，并说明「审核通过后才会替换线上版本」
- 「最近发生了什么」时间线合并提交/部署/审核事件
- **未发布、已发布、待审核、被驳回四种状态下页面都不能出现空白块或"undefined"**

### US-6 作品公开展示
> 作为访客，我扫码或点链接能看到作品，也能在集合页浏览全部作品。

**验收**（对应原型 `#collection`）：
- 集合页只展示已审核通过的正式版本，待审核/被驳回/未完成的不出现
- 显示课程主题、已上线作品数、参与人数、创作主题数
- 作品卡片含封面、标题、简介、作者（按可见性规则显示昵称或真名）、版本号、浏览量
- 支持按分类筛选
- 某作品发布新版本并通过审核后，集合页**自动**指向最新正式版本，无需人工操作

### US-7 老师课程总览
> 作为老师，我要一眼看出全班进度和谁卡住了。

**验收**（需求文档 §7.7）：
- 显示：参与人数 / 已绑定码数 / 项目数 / 未开始 / 开发中 / 待审核 / 已发布 / 被驳回
- 「长期没有进展」列表：超过 N 天（可配，默认 3 天）没有新提交的项目
- 点任一项目可进入其学员看板视图，并在此基础上获得审核操作

### US-8 AI 诊断（P0 只做可解释的那部分）
> 作为学员，我要知道我的作品现在做到哪一步、有没有坏。

**验收**：
- 每次提交后自动诊断，诊断结果**强制标注对应版本号与生成时间**
- 完成度百分比**必须**能被下方分维度得分解释；点开「查看诊断详情」能看到每一分的来源事实
- 诊断进行中时展示上次结果 + 「诊断更新中」标记，**不能显示空白或旧结果冒充新结果**
- 诊断状态与审核状态完全独立：诊断说「需要继续完善」不阻止老师发布
- 界面固定展示诊断边界声明（不等同于安全审计，老师有最终决定权）

## 5. 权限矩阵

| 能力 | 学员 | 老师/管理员 | 访客 |
|---|---|---|---|
| 查看自己的项目全貌 | ✅ | ✅（全部项目） | ❌ |
| 查看他人项目开发过程 | 仅课程内公开的 | ✅ | ❌ |
| 提交版本 / 发起部署 | ✅（仅自己的） | ✅ | ❌ |
| 查看 AI 诊断摘要与建议 | ✅（自己的） | ✅（全部，含完整依据） | ❌ |
| 审核 / 发布 / 驳回 | ❌ | ✅ | ❌ |
| 管理邀请码 / 域名 / 停用 | ❌ | ✅ | ❌ |
| 浏览已发布作品与集合页 | ✅ | ✅ | ✅（按可见性） |
| 看到邀请码明码 | ❌ | 仅生成时一次 | ❌ |
| 看到未发布版本 | 仅自己的 | ✅ | ❌ |
| 看到真实姓名 | 仅自己的 | ✅ | 仅当可见性=realname |

**实现约束**：跨越边界的请求返回 **404 而不是 403**——不泄露"存在但无权访问"这个信息。

## 6. 非功能要求

| 项 | 要求 | 理由 |
|---|---|---|
| 作品页可用性 | 由 nginx 直接 serve 静态文件，不经过应用进程 | 作品数量增长不影响平台稳定性 |
| 发布切换 | 原子，无 404 窗口 | 访客可能正在看 |
| 提交响应 | 上传完成即返回预览地址，诊断异步 | 学员不该等 10 秒看进度条 |
| HTTPS | **P0 阻塞项** | 录音/定位等浏览器 API 只在安全上下文可用，没有 HTTPS 一半作品做不出来 |
| 版本不可变 | 落盘后不再修改 | 「访客看到的是哪个版本」必须永远可追溯 |
| 错误文案 | 面向学员的错误一律中文人话 + 下一步提示 | 需求文档 §14.1 |
| 数据备份 | SQLite 文件 + versions 目录每日快照 | 单机部署，没有第二份 |

## 7. 明确的非目标（P0 不做）

- 学员部署自己的后端进程
- 学员账号体系（手机号/微信登录）〔决策 3〕
- 团队/多人协作项目
- 作品间的评论、点赞、社交
- 作品版本回滚到任意历史版本（只保留"驳回后旧版继续在线"）
- 自定义域名（学员绑自己的域名）
- 国际化 / 多语言
- 移动端 App
