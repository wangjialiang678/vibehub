# VibeHub 学员双入口提交与独立安装设计

> **2026-08-13 已部分取代**：本文保留 2026-08-12 的设计历史。其中学员网页直传、AI 部署、SkillHub 非必需和老师分发双路径仍然有效；“公开 npm 包 + `VITE_SKILL_INSTALL_COMMAND`”已由 [VibeHub 自托管 Skill 分发设计](2026-08-13-self-hosted-skill-distribution-design.md) 取代。当前路径是 `/install → VibeHub HTTPS 分发资源 → 完整性校验引导程序 → 现有本地安装器`；下文 npm 发布步骤不得再执行。

## 目标

学员收到邀请码后，无论是否使用 AI 编程工具，都能在 VibeHub 学员页明确找到“提交作品”的下一步，并完成第一次提交。

系统同时提供两条入口，但共用同一套版本、预览、诊断和老师审核流程：

1. 网页直接提交：适合已经拿到静态网页文件的学员。
2. 让 AI 帮我提交：适合需要构建项目、识别产物目录或希望 AI 整理提交说明的学员。

Skill 安装不得依赖超脑 SkillHub。SkillHub 仅作为可选的内部镜像和版本目录，停机或没有团队口令时不影响学生安装、绑定、提交或查询状态。

## 学员核心路径

`收到邀请码 → 打开 VibeHub → 输入邀请码 → 自动创建项目 → 看到“提交我的游戏” → 选择网页直传或 AI 辅助 → 生成私有预览 → 自动诊断 → 进入老师审核 → 审核通过后上线`

提交不是正式发布。网页和 AI 两条入口都必须明确说明：版本先进入私有预览和老师审核，只有老师通过后才替换正式版本。

## 信息架构与入口

### 学员首页

`/app` 的页面标题区域增加主动作“提交我的游戏”。该动作始终可发现，并根据状态调整辅助文案：

- 尚未提交：完成第一次提交。
- 有待审版本：提交新版本会替代旧的待审版本。
- 被退回：修改后重新提交，并在入口旁展示老师意见。
- 已上线：提交下一版本，不影响当前线上版本。

当前作品卡中误导性的“继续开发”改为真实动作：有预览时叫“打开预览”，没有预览时不显示灰色假按钮。

### 其他入口

- 学员侧栏增加“提交作品”。
- `/app/versions` 的空状态增加“开始第一次提交”。
- 有提交记录时，页面顶部保留“提交新版本”。
- 老师生成邀请码后，“复制发给学员的说明”同时包含 VibeHub 地址、每人一码规则、网页直传和 AI 辅助两种方式。

这些入口全部进入同一个提交面板，不复制业务逻辑。

## 提交面板

面板首先让学员选择方式，不要求理解部署术语。

### 方式一：网页直接提交

接受四类输入：

- 单个 `.html` 文件。
- `.zip` 静态网页包。
- 文件夹；浏览器读取文件夹中的相对路径。
- `.tar.gz` / `.tgz`，保留给高级用户和现有脚本产物。

表单字段：

- 作品文件，必填。
- 本次更新说明，选填，最多 500 字。
- 核心玩法，选填，最多 5 条，每条最多 80 字。

选择后先在浏览器展示文件名、格式和大小；服务端仍是安全判断的唯一事实来源。上传过程展示“正在上传 → 正在检查 → 预览已生成 → 正在诊断 → 等待老师审核”。上传成功后刷新项目和提交记录，并直接展示私有预览入口。

### 方式二：让 AI 帮我提交

展示两步：

1. 未安装时进入公开 `/install` 页面，一条命令安装通用 Skill。
2. 复制提示语：`使用邀请码 <当前邀请码由学员自行粘贴> 加入 VibeHub，然后部署我的游戏。`

网页不再次展示或保存完整邀请码。学员需要把老师发来的邀请码粘贴给自己的 AI；AI 根据 Skill 完成项目理解、构建、产物选择、更新说明和脚本调用。

如果学员已经安装，可直接复制提示语。面板同时解释：AI 方式更适合 React/Vite 等需要构建的项目；网页直传适合已有 HTML/ZIP/文件夹的作品。

## Skill 独立安装

### 主渠道

VibeHub 的公开 `/install` 页面提供 npm 一键安装命令。包发布并验证可下载后，生产构建通过 `VITE_SKILL_INSTALL_COMMAND` 开放复制按钮。

安装命令：

`npx -y @supermind/vibehub-skill@latest`

安装器把同一份 Skill 安装到 Codex、Claude Code 和 WorkBuddy 的个人目录；也允许通过参数只选择某个 Agent 或指定其他兼容 Agent 的完整目录。macOS 与 Windows 使用同一个 npm 包，运行时脚本分别调用各自系统命令。

学生不需要：

- SkillHub 地址或 token。
- 超脑内部账号。
- 手工下载和解压 Skill。
- 把 `vibehub` 加入系统 PATH。

更新前，安装器把旧版本移到 `~/.vibehub/skill-backups/`，避免覆盖个人修改，也避免备份被 Agent 当作同名 Skill 加载。

### SkillHub 的角色

超脑 SkillHub 仅同步一份相同版本，供团队内部搜索和版本留档。它不是网页安装页的依赖，不参与运行时调用，也不是 Windows 或 macOS 的兜底安装源。

### 运行时连接

安装后的 Skill 和脚本直接连接 `https://hub.supermind-ai.cn`。邀请码决定营地和项目；一个安装可以连接多个营地。SkillHub 不在请求链路上。

## 服务端架构

### 共享提交服务

把当前 `/api/skill/versions` 中的版本创建逻辑抽成共享服务，负责：

1. 验证当前凭证绑定的项目。
2. 规范化上传内容到临时目录。
3. 安全检查文件类型、路径、大小、条目数和敏感内容。
4. 校验根目录存在 `index.html`；单层目录可自动提到根目录。
5. 计算内容哈希、版本号和项目配额。
6. 修正包内绝对路径并注入 VibeHub SDK。
7. 同步扫描密钥。
8. 生成逐预览独立域名的私有预览。
9. 替代旧待审版本并启动异步诊断。
10. 非 blocker 版本进入老师审核队列。

CLI 和网页只负责把各自输入规范化后调用共享服务，不再复制提交业务规则。

提交最终化采用单调顺序：先验证预览授权，再把诊断任务入队；入队是最后一个不可回滚提交点，失败时完整恢复旧待审状态且不触碰旧产物。入队成功后才逐项清理历史产物；清理失败只记录 warning 并保留可重试的冗余产物，不回滚新版本，服务重启时继续收敛。

### 网页接口

新增 `POST /api/projects/:id/versions`：

- 仅接受当前网页 cookie 对应的本人项目；忽略客户端自报的营地或所有者。
- 使用 `multipart/form-data`。
- 文件字段 `bundle`；元数据字段 `meta`。
- 根据扩展名和文件头识别 HTML、ZIP、tar.gz，不只信任浏览器 MIME。
- 记录 `submitted_via='web'`。
- 写请求继续要求控制台同源 Origin，沿用现有 CSRF 防护。

现有 `POST /api/skill/versions` 保持兼容，记录 `submitted_via='skill'`。两者返回一致的版本、预览、诊断和审核状态结构。

### 输入规范化

- 单个 HTML：服务端放入临时目录并命名为 `index.html`。
- 文件夹：前端按相对路径打包为 ZIP 后上传，服务端不信任前端路径检查结果。
- ZIP：服务端使用 `yauzl` 的 lazy-entry 流式读取模式逐条校验并解包，不调用系统 `unzip`，不一次性把内容读入内存。
- tar.gz：继续使用现有 `tar` 模块和安全边界。

ZIP 与 tar.gz 共享同一套路径、敏感文件、可执行文件、条目数、单文件大小、总大小和项目配额规则。任何链接、设备项、绝对路径或目录穿越都让整包失败，不再“跳过危险项后继续提交”。

## 安全与资源限制

沿用现有上限：上传包 30 MB、解包后 200 MB、单文件 20 MB、最多 5000 个文件和目录、压缩比最大 100:1、项目磁盘默认 200 MB。

补充限制：

- 每个项目同一时间只允许一个提交处理任务。
- 每个项目 10 分钟最多发起 5 次网页提交；超限返回人话提示和可重试时间。
- `summary` 必须是字符串且最多 500 字。
- `flows` 必须是字符串数组，最多 5 条，每条最多 80 字。
- HTML 文件也执行完整的敏感内容扫描。
- 文件格式与声明不一致时拒绝。
- 临时文件无论成功或失败都在请求结束时清理。
- 日志只记录入口、项目 ID、输入格式、大小、处理阶段、结果代码和版本 ID；不记录文件内容、cookie、Authorization 或预览 claim。

预检继续作为 CLI 的上传优化，不作为安全授权。网页直接上传后由共享服务以实际内容哈希判重；同内容但上一版本已退回、产物被清理，或本次更新说明不同的情况允许形成新的审核提交，避免学员被历史哈希卡死。

## 错误体验

网页错误使用学员能采取行动的语言：

- 没有 `index.html`：提示选择网页首页或构建后的 `dist/build` 目录。
- ZIP/压缩包损坏：提示重新压缩或改用文件夹提交。
- 发现密钥：列出经过脱敏的文件路径，要求删除 `.env`、私钥或代码中的密钥。
- 文件过大/过多：显示当前上限，并建议压缩素材或使用平台文件存储。
- 正在提交：阻止重复按钮，并允许页面继续展示当前阶段。
- 网络中断：不假装成功；保留表单说明，允许重新选择文件后重试。
- 诊断失败：版本仍可进入老师人工审核时明确说明；存在 blocker 时说明必须修改后重新提交。

## 前端组件边界

- `StudentSubmitPage`：路由 `/app/submit`，承载两种提交方式和状态。
- `WebUploadPanel`：文件选择、元数据、上传阶段和错误。
- `AiDeployPanel`：安装入口、复制提示语和适用场景说明。
- `SubmissionCta`：首页、提交记录与侧栏复用的入口组件，只负责路由和状态文案。
- API 层新增网页提交方法，统一处理 multipart 和进度；项目查询仍由现有 Query 缓存管理。

不引入 UI 组件库，不重做现有学员看板。

## 老师分发体验

老师生成邀请码后可以复制一段完整说明，内容包含：

- 营地名称。
- VibeHub 登录地址。
- 每人使用自己的邀请码，不要互换。
- 进入后点击“提交我的游戏”。
- 已有 HTML/ZIP/文件夹时可网页提交。
- 使用 Codex、Claude Code 或 WorkBuddy 时可选择“让 AI 帮我提交”，Skill 可从公开安装页直接安装，不需要 SkillHub。

完整邀请码只在当前生成结果中进入复制文案；刷新后仍遵守现有“明码不再展示”的规则。

## 发布与回滚

发布顺序：

1. 完成数据库兼容、共享提交服务和网页接口。
2. 完成学员双入口和老师分发文案。
3. 全量测试、生产构建、Skill 校验和 npm 包内容检查。
4. 发布公开 npm 包并从一台干净 macOS 环境和一台 Windows/PowerShell 环境验证安装。
5. 可选同步相同版本到超脑 SkillHub；该步骤失败不阻塞学生发布。
6. 修复并验证 `*.preview.supermind-ai.cn` 泛解析和通配证书。
7. 原子发布服务端和控制台，生产构建同时设置安装命令。
8. 用测试营地走通“邀请码登录 → HTML 直传 → 私有预览 → 老师审核”和“Skill 安装 → AI 部署”两条路径。

服务端沿用时间戳 release 和 `/opt/vibehub` 原子软链。控制台保留上一份静态产物备份。新网页入口出现故障时，可以先关闭入口或回滚控制台；现有 Skill/CLI 提交流程必须继续可用。

## 验收标准

1. 学员用邀请码进入 `/app` 后，十秒内能看到“提交我的游戏”。
2. 首页、侧栏和提交记录页都能进入同一个 `/app/submit`。
3. 学员能分别提交单个 HTML、ZIP、文件夹和 tar.gz，并生成私有预览。
4. React/Vite 等需要构建的项目能从 AI 入口安装 Skill 并完成提交。
5. Skill 安装、运行和更新不需要 SkillHub token 或服务可用。
6. 网页与 Skill 提交共用安全检查、版本、诊断和审核流程，并正确记录来源。
7. 危险路径、链接、可执行文件、敏感文件、超额压缩包和高频提交被安全拒绝。
8. 被退回和已上线项目都能提交下一版本，当前正式版本不受影响。
9. 老师能复制包含两种提交方式的完整学员说明。
10. macOS 和 Windows 均能完成公开 npm 一键安装。
11. 预览泛域名、私有预览授权、审核发布和正式网址在线上真实可用。
12. 现有服务端、前端、Skill 和安全测试全部通过，新增功能有自动化覆盖。

## 验证方案

- 单元测试：输入格式识别、HTML 规范化、ZIP 安全解包、字段校验、频率限制、判重规则和提交来源。
- 服务端集成测试：四种输入、危险归档、cookie 鉴权、跨项目拒绝、并发提交、异步诊断和审核队列。
- 前端测试：三处入口、双面板、文件校验、上传状态、错误恢复、复制 AI 提示语和老师分发文案。
- 回归测试：CLI bind/deploy/status/open、多营地切换、旧凭证迁移和 npm 安装器备份。
- 构建检查：TypeScript、前端生产构建、服务端全量测试、Skill 快速校验、npm tarball 白名单。
- 线上探针：健康检查、安装页、npm 安装、预览泛域名、HTML 直传、ZIP 直传、老师审核和正式网址。
