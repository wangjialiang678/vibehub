# VibeHub 老师端首次使用引导设计

## 目标

老师第一次使用邀请码登录后，应在十秒内明白三件事：

1. 这是管理营地学员作品的工作台。
2. 自己负责邀请学员、跟进进度、审核发布和整理成果。
3. 当前唯一需要做的第一步是生成并分发学员邀请码。

引导完成后，后台继续用真实营地数据提示下一步，但不持续打扰熟练用户。

## 核心路径

`老师邀请码登录 → 营地总览 → 生成学员邀请码 → 分发给学员 → 查看项目进度 → 审核并发布 → 查看成果集合`

老师登录后的默认落点从空的审核页改为营地总览页。

## 信息架构

老师端左侧导航使用任务语言：

- 营地总览
- 邀请学员
- 学员项目
- 作品审核
- 成果展示

侧栏底部增加“使用帮助”入口。它打开右侧帮助面板，不离开当前工作。

## 首次登录体验

首次进入总览时，在统计数据之前显示展开的欢迎面板：

> 欢迎来到「营地名称」
>
> 这是你的营地管理后台。你可以在这里邀请学员、查看每个人的创作进度、审核作品，并把完成的作品发布到成果展示页。

面板用三段短文说明工作方式：

1. 邀请学员加入：每人一个邀请码，绑定后项目自动出现。
2. 跟进和审核作品：找到未开始、卡住或待审核的学员，发布或退回版本。
3. 展示营地成果：审核通过的作品进入公开集合，可以推荐和排序。

主要动作只有“开始邀请学员”，直接进入邀请码页面。次要动作“我先看看后台”只收起介绍，不阻塞老师浏览。

首次状态以 `user_id + camp_id` 为键保存在浏览器本地。点击任一动作即视为已看过。换浏览器或清除站点数据后再次出现完整欢迎说明，是可接受的降级行为。

## 持续任务引导

欢迎说明收起后，总览保留一张紧凑的“带营步骤”任务卡，进度由后台数据自动计算：

1. 生成学员邀请码：存在至少一个学员邀请码时完成。
2. 等待学员加入并创建项目：存在至少一个学员项目时完成。
3. 审核并发布作品：存在至少一个正式发布作品时完成。
4. 整理成果展示：发布作品后解锁，提供前往集合页的入口。

任务卡每一步同时显示当前数量和下一步动作，例如“已有 8 位学员加入”“有 2 个作品等待审核”。全部关键步骤完成后，卡片收起为“开营流程已跑通”，仍可展开查看。

为避免老师邀请码污染进度，总览接口补充学员邀请码总数和已绑定数。现有总览、项目、审核和集合接口继续作为唯一事实来源。

## 邀请学员页面

页面标题从偏系统的“发放邀请码”改为“邀请学员加入营地”，顶部说明一个邀请码对应一位学员。

表单默认选择学员身份。设备上限保留默认值 3，并解释为同一位学员最多可使用的设备数量。邀请其他老师作为次级选项保留，但不抢占主流程。

生成后进入明确的分发状态：

- 告知完整邀请码只显示一次。
- 提供“复制全部邀请码”和“导出本批邀请码”。
- 提供“复制发给学员的说明”。
- 明确提醒不要把同一个邀请码发给多人共用。

发给学员的说明包含营地名称、每人一码规则和进入 VibeHub 后的下一步，不包含任何虚构操作。

## 使用帮助面板

帮助面板按老师的任务而非页面名称组织：

- 第一次开营：生成并分发邀请码。
- 课程进行中：查看未开始、卡住和最近更新的项目。
- 学员提交后：预览作品、审核发布或填写原因退回。
- 课程结束时：推荐作品、调整顺序并打开成果展示页。
- 常见问题：邀请码丢失、发错、撤销和设备上限。

每个章节提供一个直接跳转到相关页面的动作。帮助面板可以关闭、按 Escape 关闭，并在移动端占满可用宽度。

## 空状态

空页面必须解释“为什么为空”和“下一步做什么”：

- 没有学员或项目：引导生成学员邀请码。
- 没有待审核作品：说明学员提交后会自动出现，并可返回总览。
- 没有已发布作品：说明审核通过后才进入成果展示。

所有空状态动作都使用真实路由，不出现失效按钮。

## 错误与可访问性

- 本地引导状态读写失败时，保持显示欢迎面板，不影响业务操作。
- 邀请码复制失败时保留明码并显示人话提示。
- 帮助入口和抽屉具备按钮语义、可见焦点、关闭标签和 Escape 行为。
- 任务完成不能只靠颜色表达，同时使用文字和图标。
- 手机端先显示欢迎说明和主要动作，统计数据随后出现。

## 技术边界

- 不新增数据库表或用户字段。
- 不引入 UI 组件库。
- 不制作易失效的逐元素遮罩式产品导览。
- 不改变邀请码权限、审核权限和发布流程。
- 不把现有独立使用说明全文塞进后台，只复用其中已核实的操作事实。

## 验收标准

1. 老师邀请码登录后进入 `/admin/overview`，不是 `/admin`。
2. 首次进入会看到后台用途、完整流程和唯一主动作“开始邀请学员”。
3. 点击主动作进入邀请码页，默认身份为学员。
4. 老师能复制或导出本批邀请码，并复制可直接发给学员的说明。
5. 再次进入总览时完整介绍收起，数据驱动的任务步骤仍可见。
6. 左侧导航能直接进入邀请学员，底部能随时打开使用帮助。
7. 无项目、无审核任务时都能看到原因和可执行下一步。
8. 桌面端和手机端均可完成上述流程。
9. 现有前端与服务端测试全部通过，新增路径有自动化测试覆盖。

## 验证方案

- 单元测试：老师登录落点、任务状态计算、本地首次状态键、学员说明文案。
- 组件测试：首次欢迎面板、紧凑任务卡、帮助面板、邀请码分发动作和空状态链接。
- 服务端测试：总览正确区分学员邀请码与老师邀请码。
- 构建验证：TypeScript、前端测试、前端生产构建、服务端测试。
- 线上探针：登录页、健康检查和控制台静态资源可用；用生产老师会话人工验证首次落点、邀请页和帮助面板，不生成或撤销真实邀请码。
