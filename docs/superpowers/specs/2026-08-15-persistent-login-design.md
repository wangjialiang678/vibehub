# VibeHub 长期记住登录身份设计

日期：2026-08-15

## 目标

老师和学员使用邀请码成功登录一次后，VibeHub 默认在当前浏览器长期记住身份。正常使用过程中不再要求周期性重新输入邀请码。

会话只在以下情况失效：

- 用户主动点击“退出登录”；
- 用户清除了浏览器的网站数据，或使用无痕模式；
- 老师撤销了对应邀请码；
- 平台管理员主动吊销相关会话。

## 方案比较

### 方案 A：固定 30 天

实现简单，风险较低，但不符合“登录一次后一直记住”的产品目标。

### 方案 B：永久服务端凭证 + 浏览器自动续期（采用）

网页登录凭证不设置固定服务端到期时间。浏览器 Cookie 使用浏览器允许的长周期，并在每次成功使用 Cookie 会话时自动续期。这样持续使用的设备不会再次要求登录，同时仍保留退出和邀请码撤销的即时失效能力。

### 方案 C：新增账号密码或 Passkey

安全能力更完整，但会引入新的账号体系、找回流程和较大产品改造，不适合当前营地的轻量邀请码流程。

## 用户体验

- 登录页不要求用户选择期限，成功登录后默认记住身份。
- 登录页提示：“登录后会在这台设备上记住你；使用公用电脑时，请在使用后退出登录。”
- 老师和学员使用相同规则。
- 现有仍有效的网页会话在下一次正常请求时自动升级为长期会话，不要求重新登录。
- “退出登录”继续清除浏览器 Cookie，并立即吊销当前服务端凭证。

## 服务端设计

1. `/api/session/redeem` 为网页来源签发不设固定到期时间的可吊销凭证。
2. `vh_session` 保持 host-only、`HttpOnly`、`Secure`（生产）、`SameSite=Lax` 和 `Path=/`。
3. Cookie 使用浏览器支持的长周期。每次成功的 Cookie 鉴权请求重新写入相同 Cookie，以滑动方式续期。
4. 仅 Cookie 鉴权触发续期；Bearer/Skill 凭证不写浏览器 Cookie。
5. 若当前网页凭证仍带旧版 12 小时到期时间，首次成功鉴权时清除该到期时间并续写 Cookie，完成无感升级。
6. 退出登录、邀请码撤销和管理员吊销继续以数据库中的 `revoked_at` 为权威，续期不能恢复已吊销凭证。
7. 不新增数据库表或迁移。

## 安全边界

- “一直记住”不等于无法退出：用户主动退出后，旧 Cookie 即使被恢复也不能再使用。
- 邀请码撤销会原子吊销由该邀请码签发的全部凭证。
- 不把会话凭证放入 URL、页面文字、日志或 `localStorage`。
- 公用电脑风险通过登录页提示和现有退出入口处理；本次不新增复杂的设备管理页面。

## 测试与验收

### 服务端

- 网页登录签发的 token 没有固定 `expires_at`。
- 登录响应的 `vh_session` 包含长期 `Max-Age`，并保留全部安全属性。
- 成功的 Cookie 鉴权会续写 Cookie；Bearer 鉴权不会。
- 旧 12 小时网页 token 在首次成功请求后升级为无固定到期时间。
- 已过期、已吊销 token 不能借续期恢复。
- 退出登录清除 Cookie，并使原 token 无法再次访问。
- 邀请码撤销后，长期会话立即失效。

### 前端

- 登录页明确说明当前设备会被记住，以及公用电脑需要退出。
- 老师和学员登录流程不增加额外步骤。

### 回归

- 完整服务端测试、完整前端测试、TypeScript 检查和生产构建全部通过。

## 不在本次范围

- 账号密码、短信验证码或 Passkey；
- 多设备会话管理页面；
- “记住我”期限选择器；
- Skill/AI Agent 凭证期限调整。
